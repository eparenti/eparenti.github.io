EGON
Private · not released
Last changed 27 May 2026

For one person who runs AI agents as builders and reviewers

Run builds and reviews by AI agents as workflows that survive a restart.

EGON is a local service and a command line tool. It tracks each build and its review as a workflow that is saved to disk, so the state survives a restart, a blocked agent, or a handoff. Each task carries its goal and the proof expected, and the reviewer checks the work against that.

The problem. A long build with AI agents can lose its state after a restart, a blocked agent, or a handoff. The reviewer often reads only the builder's own summary of what it did. The person in charge cannot easily see where the project stands or what is waiting on them.

You get a service that runs on your computer, a command line tool, and adapters (connectors) for Codex, Claude Code, and a hosted Claude agent. You decide what to build and whether the result is accepted. EGON keeps the workflow state, the handoffs, and the records of each run.

Work survives a restart

Each workflow, run, and decision is saved in a .egon/ folder in the repository. After a restart you can see what ran, what is blocked, and what waits on you. A run that lost its process is marked blocked and offered a retry.

Reviews check the contract

A build task carries its goal, the files that matter, the exit criteria, and the proof expected. The reviewer gets that contract and the builder's results, and records a verdict on the run.

Risky tasks stop before they start

Before an agent starts, EGON checks the task text. A protected system folder, a very large prompt, something that looks like a secret, or a destructive command blocks the start, and EGON records why.

How a request moves through EGON

You keep the decisions. EGON keeps workflow state, handoffs, and records. It does not decide what to build or accept the result. When a reviewer asks for changes, the workflow pauses until you start a follow-up or a retry.

From one sentence to a reviewed build

You give EGON a goal, a builder, and a reviewer. It runs the build, then the review, and pauses for you when the reviewer asks for changes or an agent is blocked. A retry stays inside the same workflow, so you do not start over.

Example: start and follow a workflow

Real commands
egon workflow-start "develop an app that does X" \
  --cwd /path/to/repo --builder codex --reviewer claude-code
egon workflow-detail WF-001 --cwd /path/to/repo
egon workflow-follow-up WF-001 --cwd /path/to/repo \
  --note "Address the reviewer feedback"
egon workflow-retry WF-001 --cwd /path/to/repo \
  --note "Retry after fixing the blocker"

Each command prints a short summary. Add --json for the full record. --max-review-cycles sets how many review rounds a workflow allows (two by default).

The reviewer approves

The verdict is saved on the build run with the results it reviewed. You decide what to do with the work.

Changes requested, or an agent is blocked

The workflow pauses. You read the review and start a follow-up, or fix the blocker and queue a retry inside the same workflow.

Spending and time limits

By default each Claude Code run is capped at $2.00, and a workflow stops once its recorded cost reaches $4.00. Codex runs stop after 5 minutes and Claude Code runs after 15 minutes. Environment variables change these limits. One stop action in the service stops every run it knows about.

Limits. The project is private and unreleased, and it has not changed since 27 May 2026. The browser screen for it is not in this repository: the service serves its API (the interface programs call) and a short home page. Claude Code runs without permission prompts by default, so the task checks and the spending cap are the main controls. A separate opt-in mode splits a large job into parallel parts, each with its own files, and combines them with one final verdict.

How it runs

EGON is a Python package. It runs a local service on 127.0.0.1 (your own computer only) and a command line tool.

  1. Install and start.

    Install from a copy of the repository, then run egon start. egon status, egon restart, and egon stop manage the service.

  2. Look at a repository.

    egon inspect finds the repository's root folder. egon runs and egon workflows list the saved runs and workflows.

  3. Choose your agents.

    egon adapters lists the agents EGON can start: Codex and Claude Code when they are installed, and a hosted Claude agent when you give it an API key.

Service

python3 -m pip install -e ".[dev]"
egon start
egon status

Operate

egon inspect /path/to/repo
egon runs --cwd /path/to/repo
egon review-run RUN-001 approved \
  --cwd /path/to/repo --note "Looks good to ship"

The service listens on port 8181 by default. egon review-run lets you record a verdict yourself.

The idea behind it

An AI build keeps its state when every task, result, and review is a saved record, and the person in charge makes the decisions. EGON explores that idea for one person who runs several agents.
