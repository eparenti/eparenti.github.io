For a human architect running agent builders and reviewers

Keep the architect seat. Make the build state durable.

EGON is a local control plane for human-agent software engineering. It turns intent into durable workflows, coordinates builders and reviewers, and keeps the project state inspectable after refreshes, restarts, blockers, and handoffs.

A local service and a CLI. The human owns intent, direction, and final judgment. EGON owns workflow state, handoffs, memory, and operator visibility. Builders and reviewers are attached workers with explicit assignments.

Durable workflows

A workflow queues the build run, executes or dispatches it, queues review with the builder's artifacts, and records the reviewer's verdict back onto the run. Blockers and decisions survive a restart.

Explicit handoffs

A build handoff carries the objective, source surfaces, exit criteria, and proof expectations. The reviewer reviews against that contract instead of the builder's own summary.

Guardrails before launch

Every direct-agent handoff passes guardrails before a subprocess starts. Protected paths, oversized prompts, secrets, destructive commands, and evasion instructions block with a recorded artifact.

Where EGON sits between the operator and the workers

What EGON owns. Workflow state, handoffs, layered memory, and operator visibility. It does not own intent or final judgment, and it merges nothing on its own: a reviewer's request for changes pauses the workflow for the operator.

From one sentence of intent to a reviewed build

The operator states the goal. EGON creates the workflow, dispatches the builder with a contract, queues the reviewer with the builder's artifacts, and stops for the operator when the reviewer asks for changes or a worker blocks.

Example: start and follow a workflow

Real commands
egon workflow-start "develop an app that does X" --cwd /path/to/repo --builder codex --reviewer claude-code
egon workflow-detail WF-001 --cwd /path/to/repo
egon workflow-follow-up WF-001 --cwd /path/to/repo --note "Address the reviewer feedback"
egon workflow-retry WF-001 --cwd /path/to/repo --note "Retry after fixing the blocker"

Commands print a concise operator summary. --json gives a script the full payload.

Approved: the run carries its verdict

The reviewer's verdict lands on the build run with the artifacts it reviewed, and the operator decides what ships.

Changes requested or blocked: EGON pauses

The workflow pauses for the operator to inspect the review and start a follow-up, or to queue a retry inside the same workflow instead of starting over from the prompt.

Budgets and safety defaults

Claude Code receives a per-run budget cap, workflows stop at a recorded cost ceiling, Codex and Claude Code have timeouts, and hosted-agent sessions are flagged stale after a fixed period. Environment variables override saved settings. One stop path stops all known executions even when no repository is selected.

Private today. EGON is in development and the repository is private. Codex full automation and Claude Code permission bypass are explicit opt-ins. A separate opt-in mesh mode splits a large mission into worker cells with owned paths, integration gates, and one coordinator verdict; it wraps the normal loop rather than replacing it.

How it runs

A Python package with a local service on 127.0.0.1 and a CLI. Install from source, start the service, open the page.

  1. Install and start.

    pip install -e ".[dev]", then egon start and open the local page. egon status, restart, and stop manage the service.

  2. Inspect a repository.

    egon inspect canonicalizes the repository root. session, memory, runs, and workflows read the repo-local state under .egon/.

  3. Attach workers.

    egon adapters lists what is available: Codex and Claude Code on PATH, an optional hosted Claude adapter, and an agent-collab builder dispatched through collab.py new-task.

Service

python3 -m pip install -e ".[dev]"
egon start
egon status

Operate

egon inspect /path/to/repo
egon collaboration-rail --cwd /path/to/repo
egon review-run RUN-001 approved --cwd /path/to/repo --note "Looks good to ship"

Manual claim, step, return, and verdict controls live in the page's Options.
