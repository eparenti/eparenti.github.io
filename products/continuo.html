For people who build products with AI agents

A complete build studio for people who build with AI.

You bring the ideas and your own AI agents. Continuo brings the rest of the studio: a full team of roles for your agents to perform, the order work runs in from the first idea to the release and after, the checks on every step, cost control, and one page where you make the decisions. It runs on your own machine.

The problem. One person with an AI coding agent can make a working program in an afternoon. A product is more: something a stranger can use, that is secure and documented, built for a real need, and that keeps improving. In a company, a dozen jobs stand between a program and a product. The builder with an agent has none of them, and the agent does not know they are missing.

Continuo has 17 roles, 10 lines (a line is the order the roles run in for one kind of work), and 79 checks. It is designed for the assistants you already use, such as Claude Code, Codex, and Gemini. Your agents do the work, programs check it, and you decide. Continuo itself never calls a model.

A full team of roles

Product manager, user researcher, designer, architect, engineer, code reviewer, test engineer, security, accessibility, technical writer, release manager, operations, delivery, cost, license review, and support. Each role is copied from a real job, with its sources named. Your agents perform them.

A line for every kind of work

A new product, a feature, a fix, a small chore, an experiment, a release, a patch, a rollback, a monthly review of what you learned, and a weekly support digest. Each line sets the order of the roles and what each one hands to the next.

One page for your decisions

The page lists what needs you, with the role that asks and its recommendation. You answer there, and the answer goes back to the agent that asked. It also shows what changed since you last looked and where every piece of work stands.

Guardrails for costly mistakes

An agent that continuo starts runs in a sandbox (a closed environment) with none of your credentials. Every push passes a publish gate that checks the account, scans for secrets, and checks that the work has its reviews and tests. A release needs your approval with a passkey, so an agent cannot approve for you.

Cost you can see and limit

A meter prices the model calls your assistants make. You see cost by project, by piece of work, and by role. A budget stops a run before it overspends, and a comparison tool shows which model does a role well for the least cost.

A studio that learns how you work

A practice is your own rule, check, or step. It starts on trial, continuo measures whether agents follow it and whether it helps, and you keep it or drop it. Kept practices are written into the instruction files your assistants read.

From an idea to a released product

You have an idea and your own AI agents. You open a new product, and continuo starts the product line. At each step an agent performs a role from its written definition, continuo checks the result, and you get one decision. This is the product line as the repository defines it.

The product line, step by step

From the shipped lines
STEP             WHO DOES IT                         YOUR DECISION
brief            product manager                     approve the brief
research         user researcher                     does the idea go ahead?
design           designer, with prototype tests      approve the design
plan             architect; reviewed by a code       approve the plan
                 reviewer and by security
build, in parts  engineer; each part gets a code
                 review, the tests, and security
                 and accessibility checks
docs             technical writer, then a review
release          release manager; security,          authorize the release
                 license, accessibility, and
                 test reviews assess it
after release    support digest every week,          choose what to work on
                 learning review every month

"Who does it" names the role. Your agents perform the roles, and a program runs the steps that are only checks, such as the tests. A feature, a fix, and a small chore run shorter lines. A patch and a rollback have their own lines too.

The work passes the line

Every step is done, the reviews passed, and you authorized the release. The record shows who performed each role and what it cost.

A check fails, or you skip a step

Failed work goes back to the role that made it, with what was wrong, for a set number of rounds. Then you decide. A skipped role is recorded with your reason, so you can see later what was skipped.

More in the studio

Start from where you are. continuo adopt maps a project you already have onto a line and shows which jobs were done, which were skipped, and which are missing. Starters give a new idea a template and a first slice of work.

Specialist tools for the roles. Bug finding that confirms each bug with evidence. Accessibility checks on the running app. Live checks that follow a product's own instructions on a real system. Model comparison on the same work. A product lab for experiments.

All your agent sessions on one screen. A terminal screen lists every Claude Code, Codex, and Gemini session on your machine: which is working, which is waiting for you, and which is stuck. You start and rejoin sessions from it.

Clients and teams. Each client or employer is a realm (a separate space). Your roles, lines, and practices are shared across realms, and the work is never shared. A small team can share one line, with roles assigned to people and each person's agents reviewing the other's work.

What continuo is not. It is not an agent, a model, or a chat window, and it writes no code. Your agents do the work, and you make the decisions. It runs on your machine and sends nothing anywhere unless you choose to.

A day with continuo, and where the build stands

You start and end work on one local page. Your agents keep working in your terminal or editor as before.

  1. Open the page.

    "Needs you" lists the decisions waiting, each with the role that asks, what it needs, and its recommendation. "Changed since you looked" shows what moved while you were away.

  2. Let the agents work.

    When a step is ready, continuo gives the agent its brief. The agent does the work and writes the result. Continuo checks it and moves the work on.

  3. Decide and release.

    You approve the brief, the design, the plan, and the release. Every push passes the publish gate first.

Runs today, from source

uv sync
uv run continuo projects
uv run continuo status-instructions
uv run continuo sync
uv run continuo page

Cost and settings

uv run continuo ingest
uv run continuo top --once
uv run continuo config check

These commands run today on Linux with Python 3.13 and uv, from a copy of the private repository. sync reads what your agents reported and checks it, page opens the local page, and top shows tokens and estimated cost. Planned for 0.1: continuo init for one-command setup and continuo adopt for existing projects.

What version 0.1 must show

Version 0.1 is released when 18 scenarios run end to end on clean Linux and macOS machines. They include one builder taking a product from the brief to a release, a consultant with two clients, a team of three on one repository, and an agent that tries to act as the owner and is refused.
