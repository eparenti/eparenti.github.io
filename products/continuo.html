For people who build with AI assistants

Claimed, or proven.

Continuo is an advisor with guardrails for people who build with AI. It runs on your machine beside the assistants you already use, checks what they claim against evidence, measures quality, cost, and speed, and is built to learn which ways of working pay off for you.

Each project's agent writes a status file in a fixed format. Continuo reads them into a local store, checks the cited evidence, shows what needs you, and meters tokens and cost from Claude Code and Codex transcripts.

Claimed or proven

When an agent marks work done, continuo checks the evidence it cites: a commit in the repo, a file in the repo, or a passing check. Confirmed evidence shows as proven. Missing evidence shows as claimed. Contradicting evidence rejects the claim.

A decision queue

Agents ask questions in the status file. You answer on the page or with continuo answer, and the answers are written where the agent reads them.

A cost meter

continuo ingest reads Claude Code and Codex transcripts. baseline, top, and statusline report tokens and estimated cost.

Where continuo sits beside your assistants

What proven means. The status file cites evidence and continuo found it: the commit exists in the repository, the file exists, or a check receipt reports a pass. Claimed means the evidence was not cited or not found. Rejected means the evidence contradicts the claim.

From an agent's status line to a checked claim

An agent writes that the migration is done and cites a commit. Continuo looks for the commit. If it is there, the work shows as proven. If not, it shows as claimed, and the page says so.

Example: register a project

Real format
[[project]]
id = "myapp"
name = "My app"
realm = "personal"
status = "/home/you/code/myapp/.continuo/status.toml"
repo = "/home/you/code/myapp"

realm is personal, work, or sensitive. repo is optional, and continuo needs it to check commit and file evidence. Keep .continuo/ in the project's .gitignore.

Proven

The cited commit, file, or passing check was found. The work item shows as proven on the page.

Claimed, or rejected

No evidence was cited or found, so the item shows as claimed, not proven. Evidence that contradicts the claim rejects it. Either way the page says which.

Planned, not built

A learning loop of practice cards that keep the ways of working proven to pay off; an advisor that studies your work and results and adapts its advice; a practices intake from a list of trusted sources; and a model runner with routes and budgets, with bug finding that checks each bug against evidence.

Early and private. Version 0.1.0, not published to PyPI, and the interfaces will change. The worker sandbox (bubblewrap) is used only by continuo dispatch, which is off by default.

Install from source and register one project

Linux, Python 3.13 or newer, uv, and git. Optional: agent-efficiency for check receipts.

  1. Install and register.

    uv sync, then the first continuo projects creates ~/.continuo/projects.toml with comments. Add one block per project, with absolute paths.

  2. Have your agent write the status file.

    continuo status-instructions prints the guide to add to your agent's instructions file. Keep .continuo/ out of git.

  3. Sync and open the page.

    continuo sync reads the status files into the store. continuo page prints a link with the access token and opens your browser; the link is also saved in the home folder.

Install

git clone https://github.com/continuo-dev/continuo.git
cd continuo
uv sync
uv run continuo --help

Use

uv run continuo projects
uv run continuo status-instructions
uv run continuo sync
uv run continuo page

Settings live in $CONTINUO_HOME/config.toml and must declare their schema. All paths are absolute, and configured files must already exist. continuo config check validates everything and exits 1 on an error.
