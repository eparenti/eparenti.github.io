For teams that want acceptance checks with receipts

Run the checks you name. Keep the evidence.

Verdx checks whether work meets a project's acceptance rules. It runs the checks you name, records what happened, and returns pass, fail, incomplete, or not applicable. Required checks decide. Advisory checks stay visible.

A verdx.toml lists the checks. Each attempt saves its policy, input digests, checker output, and decision under .verdx/runs/<run-id>/, and verdx replay recomputes the decision from that record without rerunning anything.

Four outcomes, no averaging

A failed test is complete evidence of failure. A timed-out test is incomplete evidence. A check that found no tests is not applicable. Findings are never averaged into a passing score.

Receipts you can replay

Replay verifies the saved artifact digests, reads the saved policy, and recomputes the decision. It does not rerun commands, touch the target, or reach the network.

Input changes are caught

The run digests every file in scope before and after. A change between the snapshots makes the run incomplete, so a receipt never describes code that moved under it.

Where verdx fits in your project

A precise meaning for pass. Every required check completed and passed on the declared input files, and those files did not change during the run. Coverage is reported separately from results: if one required check passes and another reports no tests or no matching files, the result is incomplete.

From a policy file to a replayable decision

A test suite that times out is neither a failure nor a pass. Verdx records exactly what the checker did and refuses to call it either.

Example: one required and one advisory check

Real format
version = 1
include = ["src/**", "tests/**", "pyproject.toml", "uv.lock", "verdx.toml"]

[[checks]]
id = "tests"
command = ["uv", "run", "--locked", "pytest", "-q"]
version_command = ["uv", "run", "--locked", "pytest", "--version"]
timeout = 300
not_applicable_codes = [5]

[[checks]]
id = "style-advice"
command = ["uv", "run", "--locked", "ruff", "check", "src/"]
required = false

Exit code 0 is pass, 1 is failure, and anything else is incomplete unless success_codes, failure_codes, or not_applicable_codes declare the tool's contract. Pytest returns 5 when it collects no tests.

Pass: every required check completed and passed

Exit 0. The receipt is the proof: copy the run directory elsewhere and verdx replay recomputes the same decision from it.

Fail or incomplete: the work is not accepted

A required failure exits 1. Missing evidence, a command that could not finish, or inputs that changed during the run exit 2 as incomplete. Not applicable exits 3. A domain can report a failure and incomplete coverage together, and both stay visible.

Domain plugins and the older scored interface

Markdown checks (heading order, relative links, whitespace) ship as a domain plugin, and the example domain is a template for your own. Plugins register through an entry-point group and use the public contracts; they do not import the engine.

The older validate, fix, and drive commands keep a scored pass-or-block interface with bounded repair loops. Use check when a required rule must pass without findings and you need retained evidence.

Unsigned local records. Receipts prove internal consistency. They do not prove who produced a record or defend against someone rewriting both a record and its hashes. A snapshot covers the declared local files. It does not cover remote services or the whole environment. Independent enforcement and signing belong in a trusted CI integration such as Siglum.

Add acceptance rules to one project

Verdx is an early implementation installed from source, with Python 3.13 or later. Command execution is tested on Linux.

  1. Install and check verdx itself.

    uv sync --locked --extra dev, then uv run verdx check . runs the repository's own policy: lint, formatting, type checks, tests, and documentation checks. CI runs the same policy.

  2. Write verdx.toml.

    List the files that affect results in include, including lockfiles and checker source. Declare each check as an argument list with a timeout and, where the tool needs it, its exit-code contract and a version_command.

  3. Keep and replay the receipts.

    Each attempt gets its own directory under .verdx/runs/. Copy a complete run directory to move the evidence; verdx replay returns the original decision's exit code.

Install

git clone https://github.com/ostinato-forge/verdx.git
cd verdx
uv sync --locked --extra dev
uv run verdx check . --output text

Check and replay a project

uv run verdx check /path/to/project --output text
uv run verdx replay .verdx/runs/<run-id>/receipt.json --output text

Output is JSON when piped and text in a terminal. Progress goes to stderr, so stdout stays parseable.

Outcomes and exit codes
OutcomeExit codeMeaning
pass0Every required check completed and passed
fail1A required check found a failure; other coverage gaps remain visible
incomplete2Required evidence is missing, a command could not finish, or inputs changed
not_applicable3No required check evaluated applicable work

Known generated directories such as .git, .venv, node_modules, and caches are excluded by a fixed list, which is not a full .gitignore implementation. Acceptance receipts use the verdx.acceptance.v1 format; unknown versions are rejected.

A focused first evaluation

Write a policy with your test suite as the one required check and your linter as advisory. Run it, break a test, run it again, then replay both receipts from a copy of the run directories.
