Job Assistant
Version 0.2.3 · Apache-2.0
In testing with a first user

For anyone with repeatable job tasks and Claude Code

Automate your repeatable job tasks with an assistant that learns your job.

Job Assistant builds an automation for a repeatable job task from a plain request and a real file. You say "automate this" and give it one example, such as last week's report. It builds a tool for that task, checks the tool on your example, and keeps it for next time. It learns your job as you go, so each new automation starts from what it already knows.

The problem. Every job has repeatable tasks that take hours each week. Automating them takes time and skills most people do not have. A general AI assistant can help once, but it does not know your job, it forgets what you told it, and a tool that acts for you can send or delete the wrong thing.

It runs inside Claude Code on a Mac or a Linux computer, in a terminal or in the Code section of the Claude desktop app. One install script asks at most four questions and opens the first session.

Automation from a request and a file

Say "automate this" and add a file, a screenshot, a link, or pasted text. It builds a tool, runs the tool on your example to check it, and lists the words that run it next time.

It learns your job as you go

Setup reads your job description and asks two or three questions. After that it asks only what it does not know yet and remembers the answers. A correction such as "always" or "never" becomes a rule, after a check that the rule does not break earlier results.

Nothing is sent for you

It never posts, sends, edits, shares, or deletes anything in your other systems. The settings of the assistant folder block those actions. It prepares drafts and tells you where to paste them.

How a repeatable task becomes an automation

Every result is a draft. Nothing leaves until you send it yourself. A number meant for leaders stays marked "Draft, not checked" until you approve it. Ask "is this number safe to send?" and the assistant compares it with the last published number and checks it against the method.

From a task you repeat to a tool you run by asking

You drop in a weekly report that you build by hand. The assistant builds a tool that does the steps, runs it on that report, and shows you the result. From then on you run the tool by saying the words it lists, such as "check this brief".

Example: what to say

Real phrases
"set up my job assistant"          setup from your job description
"automate this" + a file           a new tool, built and checked on your example
"check this brief"                 the tool runs, by the words it lists
"that was wrong" / "always ..."    it learns the correction, after a check
"what have you learned?"          shows the rules it learned
"is this number safe to send?"    compares with the last published number
"anything I should know?"         up to three things that need you

"show my tools" opens your tools page. "forget that" removes a learned rule. "retire" and "bring back" put a tool away or restore it.

The tool works on your example

It is kept, shown on your tools page with the words that run it, and ready for next time.

A tool breaks or gives a wrong answer

Say so. The assistant finds the cause and explains it in plain words. A correction becomes a rule only after a check that it does not break earlier results.

Status: in testing with a first user

Version 0.2.3 runs end to end from a fresh copy of the repository, with 563 passing tests. One person is testing it in a real job. Findings from that testing are still open, and the interface will change.

Limits. It does not work in Cowork, which does not load locally installed plugins. Saving drafts to Google Drive needs a claude.ai sign-in. With Vertex AI, Bedrock, or an API key, drafts stay in the assistant folder.

Install it for one person

One script checks for Claude Code and git, installs uv (the program that runs the assistant's helper) if it is missing, installs the plugin, creates the assistant folder, and opens the first session.

  1. Run the install script.

    It asks your first name, whether to use the desktop app, whether to add a shortcut, and whether to install uv if it is missing.

  2. Trust the folder and set up.

    Answer yes when Claude Code asks whether you trust the folder. The protections apply only after that. Then say "set up my job assistant" and share your job description.

  3. Update the same way.

    Run the script again. It updates the plugin and keeps your folder, tools, rules, and files as they are.

Install

bash ~/Downloads/install.sh
# or, signed in to GitHub with gh:
gh api -H "Accept: application/vnd.github.raw" repos/job-assistant-kit/job-assistant/contents/install.sh | bash

By hand

claude plugin marketplace add job-assistant-kit/job-assistant
claude plugin install job-assistant@job-assistant
claude plugin list

Options: --folder PATH keeps the assistant somewhere other than ~/job-assistant, --source PATH installs from a local copy, and --app desktop or --app terminal answers the desktop app question.

A good first test

Install it for one person with one repeatable weekly task. Automate that task from one real example, run it the next week, and correct it once. Then ask "what have you learned?"
