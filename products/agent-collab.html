For two coding agents on one codebase

A contract between two agents, kept in the repo.

agent-collab is a repo-local, asynchronous collaboration protocol for two AI coding agents. One architects: it plans tasks and reviews pull requests. One builds: it implements and opens pull requests. Git branches and pull requests are the contract boundary. The human stays out of band as tech lead.

Two layers: .collab/ files for durable task state, inboxes, and review history, and a lightweight local broker for real-time "your turn" signals.

Durable state in files

.collab/tasks/*.json is the source of truth. Claims, handoffs, reviews, and completions are recorded there, and state.json is only a derived summary.

Instant signals through a broker

A local HTTP broker on 127.0.0.1 carries claimed, PR ready, merged, and resume signals, with token auth on by default and a long-poll recv.

Branches and pull requests as the boundary

The builder pushes a branch and opens a pull request; the architect reviews the diff and records the decision. Nothing merges through chat.

Where the protocol sits between the two agents

What the protocol guarantees. Every task has one durable record with its owner, verification command, acceptance criteria, handoff summary, pull request link, and review decision. A stale task is flagged by check-stale, and doctor says whether identity, hooks, daemon heartbeat, and sync are healthy for a role.

From a task file to a merged pull request

The architect writes the task with a verify command and acceptance criteria. The builder claims it, implements, verifies, pushes, and hands off with the pull request link. The architect reviews and records the decision.

Example: one task, end to end

Real commands
python3 scripts/collab.py new-task "Add retry to the fetch client" \
  --created-by architect --assigned-role builder \
  --verify-cmd "pytest -q" --file src/fetch.py --accept "tests pass"
python3 scripts/collab.py claim TASK-001 --actor builder
python3 scripts/collab.py verify TASK-001 --actor builder
python3 scripts/collab.py handoff TASK-001 --actor builder --summary "done" --pr-url <url>
python3 scripts/collab.py review TASK-001 --actor architect --decision approve --summary "lgtm"
python3 scripts/collab.py complete TASK-001 --actor builder --summary "merged"

status summarizes the queue and next --role builder shows what is queued for a role.

Approved and completed

The review decision is recorded, the architect merges the pull request, and complete closes the task with a summary.

Changes requested, or stale

The builder addresses the feedback on the same task. In-progress or in-review work with no recent activity is flagged by check-stale, so nothing waits silently.

Where it stands. Built and used on one private product in spring 2026. The architect and builder split it demonstrates moved into a larger private studio, so the protocol is stable and not under active development. Bind the broker off loopback or disable auth only when you accept the trade.

Drop it into a repository

Copy one script into your repository, initialize the workspace, and run the broker in a second terminal.

  1. Copy and init.

    Copy collab.py into scripts/, run init to create .collab/, and add .collab/ to .gitignore: it is session state and stays out of commits.

  2. Enable the runtime per role.

    enable writes repo-local identity under .collab/runtime/, installs git hooks, and records a sync checkpoint. doctor and daemon up keep freshness enforced.

  3. Start the broker.

    brokerctl.py up starts the broker with token auth and writes the token to a per-user file so other local agents can connect. onboard prints a one-screen quickstart per role.

Workspace

cp collab.py /path/to/your-repo/scripts/collab.py
cd /path/to/your-repo
python3 scripts/collab.py init
python3 scripts/collab.py enable --role builder --actor builder --peer architect --enforce warn
python3 scripts/collab.py daemon up --role builder

Broker

python3 brokerctl.py up
python3 brokerctl.py onboard --role builder
python3 brokerctl.py recv --role builder --wait 60

An idle recv --wait 60 does not block send, history, or status from other agents.

A focused first evaluation

Run one small task through the full loop with two agent sessions: new-task, claim, handoff with a real pull request, review, merge, complete. Then read the task file and the broker history.
