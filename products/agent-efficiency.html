Agent Efficiency
Released
v0.2.2 · MIT

For developers who use a coding agent every day

Fewer wasted turns. Proof a change was checked.

Agent Efficiency is a plugin for Claude Code, Codex, and Cursor. It watches each session on your own machine, points out repeated work and repeated failures, and checks that a code change was tested before the agent says it is done.

It makes no model calls and no network requests, keeps counts in one local SQLite file, and is written with only the Python standard library.

Spots wasted work

Repeated commands, repeated failures, broad file scans, and edits with no test after them each trigger one short note in the session. Notes are capped at 3 per turn and 8 per session.

Records test results as receipts

agent-efficiency check runs a test command you listed and saves the result tied to the exact commit and file contents. When the files change, the receipt is marked stale.

Loads your own notes

A vault is a git repository of short notes about your work. Each new session gets the notes that match its folder, in at most 9,000 characters.

Where it sits in a session

A precise meaning for a passing receipt. The named command exited successfully on the exact commit and file contents recorded in the receipt. When any of those files change, the receipt is stale until the check runs again. A receipt proves the check ran. It does not judge whether the check was the right one.

From a repeated failure to one note

An agent that retries the same failing command five times burns a session without moving. The runtime notices the pattern and asks for a different approach, once.

Example: the one-line status

Real output shape
$agent-efficiency status
Agent Efficiency: advise | turns 12 | tools 48 | failures 3 | nudges 1 | cost host metric unavailable.

Typed as an ordinary chat message in Claude Code. Codex and Cursor expose the same runtime.

Check passed: a receipt is minted

The test command ran on the current files and exited cleanly. The receipt records the commit, the file digests, and the time, so a reviewer can see whether the result still applies.

Check stale or failed: the claim is not backed

A file in the receipt's scope changed after the run, or the command failed. The status says so, and in guard mode the agent cannot declare the change done until a fresh check passes.

Measure whether it is worth its cost

The reports guide describes a fair experiment: the same kind of work with the plugin in observe mode and in advise mode, compared on turns, tool calls, and failures. The data for that comparison is the same local store the plugin keeps anyway.

Kept on purpose. It never stores prompts, code, commands, tool output, or transcripts. It does not call a model, does not reach the network, and does not change what your agent writes. Cursor works from a local plugin folder only, for now.

Install it in one host, then the others

The installer sets up the plugin and the terminal command and runs a doctor check. Claude Code is the shortest path. Codex needs two plugin commands and one hook approval.

  1. Install from the release tag.

    You need Python 3.11 or newer and pipx or uv. Clone v0.2.2, run install.sh, and read the doctor line. If it prints FAILED, the lines below say what is wrong.

  2. List your checks.

    Put your project's test commands in agent-efficiency.toml. agent-efficiency check runs one and saves the receipt. The status line in your agent shows pass, fail, or stale.

  3. Pick a mode.

    advise is the default. observe records without speaking. guard holds the finish line until a receipt exists and needs explicit project consent. off does nothing.

Claude Code

git clone --branch v0.2.2 https://github.com/agent-efficiency/agent-efficiency.git
cd agent-efficiency
bash install.sh

By hand

claude plugin marketplace add "agent-efficiency/agent-efficiency#v0.2.2"
claude plugin install agent-efficiency@agent-efficiency
pipx install git+https://github.com/agent-efficiency/agent-efficiency@v0.2.2
agent-efficiency doctor

A ready setup ends with Agent Efficiency doctor: OK and the host's version line. Run /reload-plugins in an open Claude Code session or start a new one.

A focused first evaluation

Install it in Claude Code on one project, list one test command, and work for a week in advise mode. Then read the report: how often it spoke, what it caught, and whether the receipts matched the commits you reviewed.
