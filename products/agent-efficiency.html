Agent Efficiency
Released · MIT
v0.2.2 · Claude Code, Codex, Cursor

For developers who use a coding agent every day

Cut wasted work by your coding agent and record proof that changes were tested.

Agent Efficiency is a plugin for the coding agents Claude Code, Codex, and Cursor. It watches each session on your own machine, adds a short note when the agent repeats work or keeps failing, and checks that a code change was tested before the agent says it is done.

The problem. Coding agents waste turns, and each turn costs time and money. They run a command that already failed again, search far more files than the task needs, and say a task is done before they test it. The person paying for the session rarely sees where the waste happens.

You get a plugin for each of the three agents, one agent-efficiency terminal command, and an optional vault of your own notes. It makes no model calls and no network requests, keeps its counts in one local database file, and uses only the Python standard library.

Wasted work gets noticed

Repeated commands, repeated failures, searches of the whole disk, and code edits with no test after them each trigger one short note in the session. Notes are capped at 3 per turn and 8 per session.

A test result you can trust later

agent-efficiency check runs a test command you listed and saves a receipt: the result, tied to the exact commit and file contents. When those files change, the receipt reads stale.

Each session starts with your notes

A vault is a git repository of short notes you keep. Each new session gets the notes that match its folder, in at most 9,000 characters.

Where it sits in a session

What a current receipt means. The listed command exited with 0 on the exact commit and file contents recorded, and the files were the same before and after it ran. When any of them change, the receipt is stale until the check runs again. A receipt shows that the check ran and passed. It does not judge whether it was the right check.

From a repeated failure to one note

An agent that runs the same failing command again and again uses up a session without progress. Agent Efficiency notices the pattern and asks the agent to change its input or approach, once.

Example: record a check, then read it

Real commands
agent-efficiency init
agent-efficiency check unit
# Agent Efficiency check unit: pass (receipt 1)
agent-efficiency evidence list
# unit: current        (after you edit a file: unit: stale)
agent-efficiency report --days 30

$agent-efficiency status     # typed as a chat message in the agent

init writes a starter agent-efficiency.toml; change its command to your own tests. Lines that start with # show the output. The last line is an ordinary chat message, and the plugin answers it before the model sees it.

Check passed: the receipt is current

The command exited with 0 on the current files. The receipt records the commit, the file digests, and the times, so a reviewer can see whether the result still applies.

Stale, failed, blocked, or inconclusive

A file in the receipt's scope changed, the command failed, it timed out or could not start, or the check itself changed files. evidence list says which, with a reason code and the fix. In guard mode the agent is asked once to run the check again.

Measure whether it is worth its cost

This release makes no claim that it saves money or tokens. Every report ends with a line saying that observed results do not prove cause or savings. The measurement guide describes a fair test: matched tasks in observe mode and in advise mode, compared on the full cost to reach an accepted result. A local experiment ledger records the groups and the outcomes.

Kept on purpose. It never stores prompts, code, commands as typed, tool output, or transcripts. It does not call a model, use the network, or switch models. Its rules are fixed, and fixed rules can be wrong. Cursor works from a local plugin folder only, for now.

Install it in Claude Code, then the others

The installer sets up the plugin and the terminal command, then checks the setup. Codex needs two plugin commands and one approval. Cursor uses a copy of the plugin in its local plugin folder.

  1. Install the release.

    You need Python 3.11 or newer and pipx or uv. Clone the v0.2.2 tag and run install.sh. A ready setup ends with Agent Efficiency doctor: OK. If it prints FAILED, the lines below it say what is wrong.

  2. List your checks.

    Run agent-efficiency init at the root of your repository and put your test command in agent-efficiency.toml. agent-efficiency check runs it and saves the receipt. agent-efficiency evidence list shows whether each receipt is still current.

  3. Pick a mode.

    advise is the default. observe records without adding notes. guard asks for a required check before the agent stops, and needs mode = "guard" in the project file. off does nothing.

Claude Code

git clone --branch v0.2.2 https://github.com/agent-efficiency/agent-efficiency.git
cd agent-efficiency
bash install.sh

By hand

claude plugin marketplace add "agent-efficiency/agent-efficiency#v0.2.2"
claude plugin install agent-efficiency@agent-efficiency
pipx install git+https://github.com/agent-efficiency/agent-efficiency@v0.2.2
agent-efficiency doctor

Then run /reload-plugins in an open Claude Code session, or start a new one. Version 0.2.2 moves the database to a format that older versions cannot open, so when you upgrade, update the terminal command and every agent plugin together. The upgrade guide has the steps.

A good first test

Install it in Claude Code on one project, list one test command, and work for a week in advise mode. Then run agent-efficiency report --days 7 and read how often it added a note, what it caught, and whether the receipts matched the commits you reviewed.
