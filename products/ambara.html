For developers and teams who use coding agents

Context that survives the session.

AI coding agents forget everything between sessions. Ambara gives them shared project context in a git repository of reviewed Markdown: decisions, handoffs, workflows, and status that the next agent reads before it touches code.

You talk to your agent the way you already do. Say "save where I left off" or "record that decision" and Ambara files it. Durable facts go through a review branch; handoffs expire on their own.

Facts with provenance

Decisions and workflows are Markdown files with YAML frontmatter in a normal git repository. History, review, and authorship stay visible outside any one agent client.

Value shown as restraint

Startup packets are compact. Full bodies stay deferred until an explicit read, and a local ledger estimates the tokens Ambara avoided sending.

Nothing tracked that was not asked for

No log of what agents read, no presence, no activity feeds. Durable context stores only what you explicitly save, and credential-shaped text is blocked before any write.

Where Ambara sits between your agents and your knowledge

A precise meaning for saved. A handoff or status note is recorded directly and expires on its own. A decision or workflow is proposed on a review branch, and Ambara says whether it opened a review request or only created the branch. Nothing becomes durable team context without an explicit write.

From "what did we decide" to a sourced answer

A new session asks about the auth migration. Instead of guessing, the agent reads the decision the team recorded, with its date, status, and the projects it applies to.

Example: a saved decision

Real entry format
---
type: decision
title: Use gRPC for internal services
status: active
projects: [api-platform]
created: 2026-01-15T10:00:00Z
---

REST endpoints between auth and billing are creating versioning friction.
Use gRPC for all new internal service communication. REST stays for public APIs.

Entry types: active (expires on its own), project, decision, workflow, and principle. Decisions and workflows go through the reviewed path.

The next agent starts informed

Startup returns the handoffs, decisions, and status that match the project, in a compact packet, with full bodies deferred until the agent asks for one.

Nothing leaks, nothing is invented

A credential-shaped string is blocked before a durable write. If only a branch exists, Ambara says so instead of claiming a review request. Reported savings are estimates with stated ranges.

Project sources, read as context

Ambara can read labeled GitHub pull requests, GitLab merge requests, and Jira issues from configured sources and surface them as project context: continue, reuse, revise, pause, handoff, or clarify. Linear and Confluence are fixture-backed previews, and promote can turn a labeled artifact into reviewed knowledge, dry-run by default.

Commit-driven capture in CI, on GitHub Actions and GitLab CI, files entries from explicit ambara: commit messages through the same content-policy gate as interactive writes.

What Ambara does not claim. It is not a secrets manager, observability product, agent runtime, or total model cost meter. It does not prove who read what, infer presence, or bypass git review. Client-specific support is claimed only after that client has been smoked.

Try the no-network proof, then connect a project

The demo builds a knowledge repo, a wired project, a fixture signal source, and a proof script that runs without a network. Then one command onboards a real project.

  1. Run the demo first.

    Python 3.12 or newer. Earlier PyPI releases were withdrawn, so install from the repository. ambara demo then ./run-proof.sh proves startup, reads, writes, review branches, capture, and value receipts locally.

  2. Onboard a project.

    ambara onboard creates a local context repo, adds agent instructions to your CLAUDE.md, configures the MCP server, and enables handoffs. Restart your coding agent.

  3. Share it with a team.

    ambara onboard --remote <git-remote-url> points everyone at one context repository on GitHub or GitLab. ambara doctor --check-startup verifies sync.

Install and prove

git clone https://github.com/ostinato-forge/ambara && cd ambara
pip install -e .
ambara demo && cd ambara-demo && ./run-proof.sh

Connect a project

cd your-project
ambara onboard --yes
ambara doctor --check-startup

ambara startup can also write a plain context file that any agent can read, and ambara html renders a static browser of the context for direct inspection.
