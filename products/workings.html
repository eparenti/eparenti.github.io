For anyone who wants to understand how a system works, starting with language models

Learn how things work by playing with the real thing.

Workings is a training platform built like an arcade game. Each lesson puts a real, working system on the screen. You set the controls, predict what will happen, run it, and see whether you were right. The first course teaches how a language model (the kind of AI that writes text one word at a time) works, and it runs a small model in your browser.

The problem. Most training explains a system with words and pictures. Learners memorize the descriptions without seeing how the system behaves, and they cannot test what they think they know.

You get the arcade app, the engine that runs the model in the page, and one complete lesson: "Why the same question gets different answers". The app needs no server and no API key.

You learn from what the real system does

Each run uses a real model. The probabilities on the screen are the numbers the model computed, and the word it picks is drawn from those numbers.

You predict first, then check

Before a round, you choose what you expect to happen. When the round ends, the lesson compares your choice with the runs you made and tells you what happened.

A small model runs in your browser

The model is a one-layer transformer (the design that large language models use, at a much smaller size) with a 52-word vocabulary. It was trained in advance and ships with the app, so nothing is sent to a server.

How a lesson runs in your browser

What you see is what the model computed. The scores on the screen come from the model running in your page. The model is small, so its sentences are simple. The controls, which set how the model picks each word, work the same way as the settings with the same names in larger AI tools, on a much larger word list.

What the first lesson teaches: why the same question gets different answers

The lesson uses one prompt, "mara met omar at the", and asks the model for the next four words. You change the sampling settings (the rules for how the model picks a word from its scores) and watch the endings change.

Example: the steps of the first lesson

Summarized from the lesson file
1. Read       Same question, different answers
2. Read       The machine you are about to drive
3. Play       Temperature 1, three runs. Predict: same or different endings?
4. Read       What you just watched (sampling)
5. Play       Temperature 0, three runs. Predict again.
6. Read       A dial that cuts instead of reshaping (top-k)
7. Play       Temperature 1 and top-k 3. How many words can win each draw?
8. Recap      What you can now explain
9. Free play  Every dial unlocked, including top-p

Temperature reshapes the odds before the model picks a word. At 0 it always takes the highest-scoring word. Top-k keeps only the k highest-scoring words. Top-p keeps the top words until their shares reach a set total.

Your prediction matches your runs

The lesson says so and names what happened. Your runs stay on the screen, and you can replay any of them one word at a time.

Your prediction does not match

The lesson says so and names what your runs actually showed. The next reading panel explains why.

Status: early build, one lesson playable

Version 0.0.1. The arcade app, the engine, and one complete lesson run from a fresh copy of the repository, and the README states 158 passing tests. Later lessons are not written yet. The engine already holds parts that no lesson uses yet: a byte-pair encoding tokenizer (it splits words into smaller pieces), a bigram model (it predicts from the previous word only), and a replay of saved training curves.

Limits. The model knows only 52 words, so it can show how the next word is chosen but cannot hold a conversation. The platform is meant for any topic, but each new topic needs its own engine, and today only the language model course exists.

Run it on your own computer

You need Node.js 22 and npm. Copy the repository, install the packages, and start the development server.

  1. Install and start.

    Run npm ci, then npm run dev, and open the address that Vite (the development server) prints.

  2. Run the checks.

    npm test checks the types, then runs the test suite. npm run build makes the production build in dist/.

  3. Run the browser check.

    npm run sweep builds the app, plays the lesson from the coin screen to free play using only the keyboard, and runs an automated accessibility check on each screen.

Run

git clone https://github.com/ostinato-forge/workings.git && cd workings
npm ci
npm run dev

Check

npm test
npm run build
npm run sweep

To add a lesson, write a lesson file in src/lessons and add it to the list in src/lessons/index.ts. npm test then runs the lesson checks on it.
