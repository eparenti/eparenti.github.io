For Ansible Automation Platform engineers

Verify the network after the change.

Converg checks whether the network reached the state your automation expressed. It derives checks from executed tasks, reads the devices, and returns a verdict with evidence.

Add network verification to the same AAP job that makes the change. Keep your resource modules, inventory, and device connections.

Use the intent you already wrote

Supported tasks supply the expected state. There is no separate verification specification to maintain.

Check the network itself

Independent device reads check configuration and supported operational state after the change.

Make the result reviewable

Each verdict names its scope. Evidence records the checks, observations, and unclaimed coverage.

Where Converg fits in your AAP job

A precise meaning for PASS. Every required check in the sealed scope must be proven, and the scope must contain at least one check. Unsupported tasks and fields stay visible as unclaimed coverage. A PASS does not certify them.

From a BGP change to a network verdict

A resource module can complete while its neighbor session remains down. Converg checks the supported configuration and the resulting session state.

Example intent: add a BGP neighbor

Illustrative task excerpt
cisco.ios.ios_bgp_global:
  config:
    as_number: "65001"
    neighbors:
      - neighbor_address: 10.100.0.2
        remote_as: "65002"
  state: merged

Assumes the peer and network prerequisites are configured. This excerpt shows the intended relationship; it is not a complete peering playbook.

PASS: the required state is proven

The observed configuration matches, the required session is Established, and every other check in scope is proven. The result states the devices and domain covered.

FAIL: a required check is not proven

A wrong remote AS, a session that does not establish within the read policy, or a missing required observation prevents PASS. Enforce mode fails the play.

Also inspect what the change did not name

Preservation checks are on by default. Converg examines supported subjects outside the expressed change that appear in the same device reads. An optional converg.verify.baseline play records state before the first change.

The evidence determines the claim. A healthy final read proves health at that point. A continuity claim needs suitable timing or baseline evidence. Refuted preservation blocks enforcement. Unknown preservation remains visible and does not block. Other read domains and untouched devices remain outside the claim.

Keep operational decisions with your team. Converg verifies expressed intent. It does not judge whether the intended design is correct, perform general reachability tests, monitor continuously, or repair and roll back changes.

Put verification at the end of the job

Use an execution environment containing Converg and the required vendor collections. Enable capture before the run, then add the final verification play.

  1. Prepare the execution environment.

    Use a reviewed development build of converg.verify. The project tests ansible-core 2.19–2.21 with specific Python and collection versions. Match the documented matrix.

  2. Keep the verification play reachable.

    Include localhost in the inventory and job limit. Device inventory and credentials must allow the verification reads. Skipping the final play produces no Converg verdict.

  3. Choose how the verdict affects the job.

    enforce is the default. audit reports a completed verdict without failing the play for a FAIL. An incomplete verification fails in both modes.

ansible.cfg

[defaults]
callbacks_enabled = converg.verify.capture

Last play, after your change plays

- name: Verify the network change
  hosts: localhost
  connection: local
  gather_facts: false
  roles:
    - role: converg.verify.run

Optional initial evaluation: set converg_mode: audit. Converg does not change the failure behavior of your earlier tasks.

A focused first evaluation

Start with one supported BGP change on lab routers. Run a healthy case and a deliberate session failure. Review the verdict, unclaimed coverage, and retained evidence with the engineers who approve network changes.
