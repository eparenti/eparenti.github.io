Product Lab
Research prototype
standard library only

For people shaping a product with an assistant

Test the alternatives before you argue about them.

Product Lab is an assistant skill and a local experiment engine. The assistant drafts the product context around its audience, the engine runs alternatives with trusted local evaluators, and a report says whether a lesson helped later work.

The demo runs from a fresh clone with Python 3.11 and the standard library. No model, GPU, network, or installation is needed to see the machinery.

Context the metrics refer to

Personas, empathy maps, journeys, outcomes, quality tradeoffs, requirements, and craft intent. Each metric points back at that context, so a number cannot float free of who it is for.

Predeclared, recorded, checked

Candidate and evaluator snapshots, hypotheses declared in advance, raw observations, durable records, and digest checks before evidence is used.

A reserved validation

Each study proposes lessons and keeps one reserved comparison to test them, with a separate control for a harmful generalization.

Where the engine sits next to the assistant

What a supported lesson means. A lesson is scoped to its recorded study: it survived the reserved validation comparison in that study, with observed variability and explicit uncertainty stated. Observed ranges describe repeated runs; they are not statistical confidence intervals.

From a product brief to a validated lesson

The bundled demo observes failed recovery attempts, derives two conditional remedies, and tests them on reserved jobs. A separate control tests a harmful generalization. The examples demonstrate the machinery; their invented workloads do not establish real-world improvement.

Example: the three commands

Real commands
python3 lab.py brief --product PRODUCT.json
python3 lab.py demo --output generated/first-demo
python3 lab.py report --lab generated/first-demo/study

Choose a new output directory on each demo run. Existing evidence is preserved.

A lesson is supported

It passed its reserved validation with the required checks met, and the report states the variability and uncertainty around it.

A lesson is not supported, or the control caught a harmful generalization

The report says so. Negative results are kept with the same records as positive ones.

Use it through an assistant

Ask an assistant to read and use skills/product-lab/SKILL.md for your idea. The skill drafts product context from available information instead of asking you to fill out JSON. Plugin manifests for Codex and Claude Code are included; host execution still needs a real usage trial.

Evidence boundary. Evaluators run with the caller's permissions, and this version is not an execution sandbox. The local record store is not an independent authority against a malicious process with the same permissions. Model costs and authoring time are not fully accounted for. Real user value, accessibility, security, and craft need evidence suited to the actual product.

Run the demo, then bring a product

Everything runs from a clone with Python 3.11 or later. Ruff is an optional development tool.

  1. Run the bundled demo.

    brief, demo, and report show the full loop on synthetic data in a minute.

  2. Draft your product context.

    Start from PRODUCT.md and PRODUCT.json, or let the assistant draft them from what you already have.

  3. Point evaluators at your product.

    Use trusted local code for evaluators. Keep validation data reserved by the workflow, and treat cross-study reuse as something to review.

Demo

git clone https://github.com/product-lab-ai/productlab.git && cd productlab
python3 lab.py demo --output generated/first-demo
python3 lab.py report --lab generated/first-demo/study

Checks

python3 -m unittest discover -s tests -v
ruff check .

To try the skill in Claude Code from a project directory: claude --plugin-dir /absolute/path/to/product-lab, then ask it to use Product Lab on an idea.
