For researchers in verifier-governed agents

Models propose. Contracts constrain. Evidence admits.

Just-in-Time Cognition asks whether some competence can move from an opaque proposal model into explicit task contracts, live evidence, permissioned tools, and reusable capabilities whose validity conditions stay inspectable.

The repository separates three levels of claim so that none borrows credibility from the others: kernel guarantees that can be tested now, systems hypotheses that need controlled experiments, and a long-term conjecture that is an empirical possibility.

Kernel guarantees

Conditional invariants about admission, permissions, provenance, and declared-dependency invalidation. Specified, implemented, and tested on finite cases now.

Systems hypotheses

Claims that contracts and evidence-directed planning improve reliability or efficiency. These require controlled experiments and are not asserted.

The conjecture, kept separate

Reusable verified capabilities may reduce dependence on the proposal model over a task stream. Stated as a possibility, with kill criteria written first.

Where the kernel sits

What passing tests mean here. They demonstrate conformance of this implementation to the specified finite cases, including bounded state-sequence exploration and real no-shell subprocess execution. They do not prove verifier soundness, contract quality, dependency completeness, process isolation, or the research thesis.

From a contract to an evidence envelope

The first end-to-end contract authorizes one command over the repository, hashes the inputs before and after, and turns the exit record into verified evidence or an unresolved envelope.

Example: run the kernel self-check contract

Real commands
PYTHONPATH=src python3 -m jitc \
  examples/kernel-self-check.ecir.json \
  --repo . \
  --allow-executable python3

# after changing a file named in the manifest, measure the new digest first
PYTHONPATH=src python3 -m jitc examples/kernel-self-check.ecir.json --repo . --measure-environment

The executable allow-list is a host decision independent of the contract.

Complete: the observation satisfied the verifier

The envelope records the contract, the measured environment, the exit record, and the verifier's result.

Unresolved: the evidence is not enough

A mismatch, a refused admission, or a verifier that could not decide produces an unresolved envelope. Nothing is assumed.

Stage B: can interventions be measured?

The experiment harness evaluates immutable registry checkpoints with identical task sets and budgets under an original and an intervention proposer. Its constructed manual-reuse upper bound uses oracle labels and an exact adjudicator. Its declining intervention-loss curve validates the measurement mechanism. It does not validate the competence-migration thesis.

A repository-fixture pilot executes patched fixture code with behavioral adjudication and classical baselines. It is safe only for the repository's trusted static candidate generators.

Claims not made. No prior-free intelligence, no open-world truth, no assumption-free reasoning, and no near-term elimination of pretrained models. The adapter does not block network or other ambient process privileges.

Read the program, then run the kernel

The notes carry the argument; the code carries the finite guarantees. Read them in that order.

  1. Read the three passes.

    The working note holds the original vision and internal debate. The adversarial stress test lists objections, required repairs, baselines, and kill criteria. The research proposal is the first formalized pass.

  2. Read the formal core and the protocol.

    State, transitions, assumptions, and conditional theorems in the formal core; the empirical path from assurance wrapper to competence migration in the experiment protocol.

  3. Run the kernel and the harness.

    python3 -m pytest for the finite cases, python3 -m jitc.experiment for the Stage B identification check, and python3 -m jitc.repository_pilot for the fixture pilot.

Verify

git clone https://github.com/ostinato-forge/jit-cognition.git && cd jit-cognition
python3 -m pytest

Stage B

PYTHONPATH=src python3 -m jitc.experiment --include-outcomes
PYTHONPATH=src python3 -m jitc.repository_pilot
