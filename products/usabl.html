usabl
Early release
v0.2.2, not on npm yet

For teams that ship web UI with coding agents

Prove the change added no accessibility barrier.

usabl checks the screens a code change touches, in a real browser, while the code is being written. It returns one verdict and says what it could not check.

Add an accessibility gate to the places you already work: the terminal, the dev server, the assistant's Stop hook, the pull request, and your Playwright tests. One engine runs behind all of them.

Only new barriers block

Barriers already in the app are recorded as an evidence floor. The gate blocks a new barrier above that floor, so you can adopt it without fixing everything first.

Repeatable checks, no model

Results come from axe-core, a PatternFly rulepack, and a keyboard walk in Chromium. An AI assistant can fix a barrier. It does not decide the result.

A verdict with a receipt

A verified run mints a receipt tied to the source tree, the policy hash, and the engine and scanner versions, so it can be re-checked later.

Where usabl fits in your workflow

A precise meaning for verified. On the screens usabl checked, the change added no new barrier a machine can detect, compared with the barriers already recorded. A run that checked nothing, or could not finish, returns no verdict, and no verdict is never counted as a pass. Verified does not mean the app is accessible or compliant.

From a changed component to a verdict

A modal that loses its focus trap passes a visual review and breaks keyboard users. usabl sees the change, scans the screen, and refuses to call the change done.

Example: what a blocking run reports

Illustrative output
npx usabl check
Screens checked: 1 of 1 mapped (settings)
New barriers: 1
  settings › dialog: focus is not trapped (keyboard walk)
Verdict: regression (exit 1)
Not covered: none

The shape is illustrative. The real report names the screen, the rule, the element, and the layer that found it.

Verified: no new barrier on the checked screens

Every mapped screen rendered and scanned, nothing new appeared above the floor, and no coverage gap was found. A receipt records the tree, policy, and versions.

Regression or not covered: the change cannot be called done

A new barrier blocks with exit code 1. A screen usabl could not check is reported as not covered rather than guessed. The Stop hook, the required CI check, or your own script turns either into a block.

Also checks the docs, and keeps the debt shrinking

With a usabl.docs.json manifest, the same run scans the product's published documentation pages with a docs rule profile and ends in one verdict or none.

When two scans of main confirm a fix, its slot in the floor closes so a new barrier cannot take it. usabl debt lists what remains and how old it is.

Keep expert judgment with your team. usabl mechanically checks 21 of the 55 WCAG 2.2 Level A and AA criteria. It does not claim compliance, replace audits or testing with people who use assistive technology, or judge whether alternative text is useful. The virtual screen reader check is built and tested but is not part of the result yet.

Put the gate where the code is written

Build the release from source next to your app, draft the configuration from your code, record the barriers already there, then install the surfaces you use.

  1. Build from a release tag.

    usabl needs Node.js 22 or later and is not on npm yet. Clone the v0.2.2 tag, build it, install Chromium for Playwright, and add it to your app as a file dependency.

  2. Draft, review, commit.

    usabl init drafts the config and route map from your code. usabl baseline scans every mapped screen twice to draft the evidence floor. Commit each file before the next step: usabl does not trust policy files with uncommitted changes.

  3. Install the surfaces you use.

    One command each for the dev-server overlay, the Claude Code Stop hook and skills, the Cursor hook, and the GitHub Actions gate. usabl doctor reports what is set up and what is missing.

Build and link

git clone --branch v0.2.2 https://github.com/usabl-dev/usabl.git
cd usabl && npm ci && npm run build
npx playwright install chromium
cd ../your-app && npm install --save-dev file:../usabl

First run

npx usabl init
npx usabl baseline
npx usabl check
npx usabl install --ci

In CI the pull request is built in a job with no secrets and judged in a separate job, so the app must build to static files and appBaseUrl must be a loopback address with a port.

Route discovery is built for React apps. The overlay supports Vite and webpack-dev-server; rspack and Next.js are not supported yet. Screens behind a login need a saved session from usabl session. usabl has not been load tested against a large fleet of applications.

A focused first evaluation

Point usabl at one React app with a known barrier, or at the usabl-app sample. Record the floor, break a modal's focus trap, watch the gate block, repair it, and read the receipt with the people who approve accessibility.
