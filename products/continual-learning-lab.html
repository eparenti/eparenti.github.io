continual-learning-lab
Research lab · Apache-2.0
Five preregistered studies

For people who study how models learn new tasks without losing old ones

Test how small models learn new rules without forgetting old ones.

The lab trains a small neural model on a sequence of new rules and asks two questions. Can it learn each new rule without losing the earlier ones, at a fixed training budget? And can what it learned earlier help it learn related rules from fewer examples? Each study is preregistered: the plan and the pass rule were written down before the scored run.

The problem. When a model learns something new, it often forgets what it learned before, so the usual fix is to keep all the old data and train on it again. Research on this problem is easy to bend: it is tempting to pick the success measure after seeing the results and to leave failed runs out.

Five studies have run, after a first pilot. They compare training on current examples only, replay (mixing a small store of old examples into each training batch), keeping every old example, separate networks for each task, and reusing learned features. Each study folder holds its plan, its pass rule, its report, and its chart.

The pass rule comes first

The plan, the seeds (the starting values for each repeat), and the pass rule are fixed before scoring. A new scored study needs a copied plan with seeds that no earlier study used.

Failed results stay in

Four of the five studies missed their own pass rule. Their reports stay in the repository, unchanged, next to the one that passed.

Results are checked before they count

Before scoring, a check reproduces saved model states and confirms that every training example drawn came from data the method was allowed to use.

How one study runs

What a pass means here. A method passes when enough seeds, usually eight of ten, meet every fixed target, such as a final accuracy floor and a limit on how much earlier accuracy it may lose. The results describe one family of generated tasks at a fixed budget. They do not show a replacement for large-model pre-training (training a large model on huge amounts of general data first).

What the studies found

One of the five studies passed its rule, and the repository explains that pass by the shape of the test. The last study shows the method most clearly: earlier learning helped on new related tasks, and the study still failed its own transfer rule. The result is kept exactly as reported.

Example: the transfer study's scored table

From the report
Method                     Labels per new task   Mean test accuracy on new tasks
Learned frozen features    128                   91.90%
Random frozen features     128                   69.85%
Fresh model                128                   87.68%
Fresh model                512                   93.64%
Independent networks       512                   93.76%
Linear reference           512                   88.37%

Frozen features means the model keeps the hidden layers it learned on four earlier tasks and trains only a new output layer for each new task. Among other targets, the rule asked it to come within two points of a fresh model given four times as many labels, in eight of ten seeds. Four seeds did. Six missed, by 2.25 to 3.17 points.

The one pass, and why

Independent small networks, one per task, reached 94.0 percent final accuracy with no measured forgetting and passed in all ten seeds, storing no old examples. The report explains why: each task's identity is given and the tasks are independent, so learning one task never changes another's weights. They also share no learned knowledge.

The four misses

A larger replay memory improved retention, but no size passed. No share of old examples in each batch passed. A controller that adjusted the share did worse than a fixed half-batch share, two seeds of ten against nine. Learned features helped on new tasks and still missed the transfer rule. All four reports are kept.

Proven, open, and not tested

Shown in this setting: replaying old examples reduces forgetting compared with training on current examples only, and separate networks avoid forgetting when task identity is given. Open: whether reused features can save total learning cost. In the transfer study the learned-feature model used about 4.44 times the estimated training arithmetic of independent networks, and the study does not show a lower total cost. Proposed but not run: a smaller shared feature model under a fixed total cost budget.

Limits stated by the repository. The rules are generated and have straight-line boundaries. Task identity is given, and each new task's examples arrive all at once with correct labels. Run times under the launcher are not comparable with earlier runs made without it. The repository notes that more variants of this benchmark are unlikely to answer the broader question of learning without large pre-training runs.

Reproduce a study, or run a new one

The lab needs Python 3.12 or later and PyTorch on CPU. Run tests, studies, and checks through the launcher.

  1. Set up the environment.

    Create .venv and install PyTorch for CPU, NumPy, and Matplotlib. The README points to a requirements.txt, but that file is not in the repository at this revision.

  2. Run the tests through the launcher.

    The three launcher tests run on their own, outside the launcher, because they start limited child processes themselves.

  3. Run a study from a copied plan.

    A new scored study needs a copied plan, unused seeds, and a pass rule fixed before scoring. The partition and transfer studies refuse to start without the launcher. The analysis script checks the evidence before it scores and writes the report.

Tests and a study

git clone https://github.com/ostinato-forge/continual-learning-lab.git
cd continual-learning-lab
python3 -m venv .venv
python3 limited_run.py .venv/bin/python -m unittest discover -s tests -p test_transfer.py -v
python3 limited_run.py .venv/bin/python transfer_study.py --plan PATH_TO_NEW_PLAN
python3 limited_run.py .venv/bin/python analyze_transfer.py STUDY_DIRECTORY

Launcher tests, outside the launcher

.venv/bin/python -m unittest discover -s tests -p test_resource_limits.py -v

Press Ctrl+C to stop a job; the launcher stops the child process and keeps a record of the outcome. Logs, limits, and resource samples go to checks/limited. A job stopped by the memory limit can leave incomplete evidence. The repository asks you to keep it.

The five studies and their outcomes
StudyQuestionOutcome
Memory sizeHow large must a replay memory be to pass at a fixed budget?No size passed. The two largest kept old rules but slowed new learning too much
Replay shareWhat share of each batch should be old examples?No share passed. Less replay helped new learning and hurt retention
Adaptive replayDoes a controller that adjusts the share beat a fixed half-batch share?No. Two of ten seeds passed, against nine for the fixed share, with extra monitoring work
Task partitionsDo independent networks avoid forgetting at about the same model size?Yes, in all ten seeds. They share no learned knowledge between tasks
Shared feature transferDo learned frozen features help on new related tasks?They helped, and missed the fixed rule: four of ten seeds

The lab is a maintained research project. The next test it proposes, a smaller shared feature model that must meet a fixed total cost budget including the first learning, has not run.

How to engage

Read one report end to end, including what the check does not test. Then copy a plan, pick unused seeds, fix a rule, and run it under the launcher.
