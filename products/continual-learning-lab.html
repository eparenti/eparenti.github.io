continual-learning-lab
Research lab
five preregistered studies

For people studying learning without forgetting in small models

Fix the rule before the run. Keep the negative results.

The lab runs a small neural model on a sequence of new rules and compares learning from current examples, replaying a small memory, retaining all earlier examples, separating task networks, and reusing learned features. Each study's protocol and decision rule are fixed before the first scored run.

Five studies have run under preregistered protocols. Each study folder holds its plan, decision rule, report, and chart. Runs are resource-limited by a launcher, and verification reproduces checkpoints and audits every training draw before a result is scored.

Preregistered

The plan, the seeds, and the decision rule are fixed before scoring. A new scored study needs a copied plan with unused seeds and a rule fixed in advance.

Resource-limited

A launcher runs each job on one low-priority CPU with a hard 2 GiB address-space limit, a memory watchdog, and a refusal to run two lab jobs at once.

Verified after the fact

Verification reproduces checkpoints, audits the training draws, and confirms data separation, protected parameters, and saved decisions before a result is scored.

Where a study runs

What a result means here. A method meets the rule when the required number of seeds pass every fixed target, such as a final-accuracy floor and an allowed loss on earlier tasks. Results describe one synthetic task family at a fixed budget. They do not establish a replacement for large-model pre-training.

From a fixed rule to a kept result

The shared-feature transfer study shows the discipline. Earlier learning helped on new related tasks, and the study still failed its own transfer criterion. The result is kept exactly as reported.

Example: the transfer study's scored table

From the report
Method                     Labels per new task   Mean test accuracy on new tasks
Learned frozen features    128                   91.90%
Random frozen features     128                   69.85%
Fresh model                128                   87.68%
Fresh model                512                   93.64%
Independent networks       512                   93.76%
Linear reference           512                   88.37%

Four of ten seeds met every condition; eight were required. Six seeds missed the two-point margin against the fresh model with 512 labels, by 2.25 to 3.17 points.

The rule is met

Independent small networks reached 94.0 percent final accuracy with no measured forgetting and met the rule in all ten fresh seeds, storing no old examples. The report also says why: with task identity supplied and independent tasks, learning one task never changes another's weights.

The rule is missed

Adaptive replay performed worse than fixed 50 percent replay, meeting the rule in two of ten seeds while adding 7,680 probe evaluations per model. Learned features helped and still missed the fixed transfer criterion. Both results are kept with their reports.

The studies so far

Memory replay at a fixed budget, two follow-ups, adaptive replay, task partitions, and shared feature transfer. Each report states which costs are measured and what verification does not test. The proposed next test, a smaller shared feature model with stored frozen features under a fixed total cost budget, has not been run.

Scope stated. Task identity is supplied and the benchmark's tasks are independent, which separate networks exploit; adding tasks would need another capacity decision. Wall times under the throttled launcher are not comparable with earlier unthrottled studies. More variants of the independent-rule benchmark are unlikely to answer the broader question about learning without large pre-training runs.

Reproduce a study, or run a new one

Python 3.12 or later and PyTorch on CPU. Run tests, experiments, and report verification through the limited launcher.

  1. Run the tests through the launcher.

    The three launcher tests run separately because they create limited child processes themselves. Do not include them in a suite inside the launcher.

  2. Run a study from a copied plan.

    A new scored study needs a copied plan with unused seeds and a decision rule fixed before scoring. The partition and transfer studies refuse to start without the launcher.

  3. Verify and read the report.

    The analysis script reproduces checkpoints and audits draws before scoring. Each study folder keeps the plan, rule, report, and chart; raw run data stays out of the repository.

Tests and a study

python3 limited_run.py .venv/bin/python -m unittest discover -s tests -p test_transfer.py -v
python3 limited_run.py .venv/bin/python transfer_study.py --plan PATH_TO_NEW_PLAN
python3 limited_run.py .venv/bin/python analyze_transfer.py STUDY_DIRECTORY

Launcher tests, outside the launcher

.venv/bin/python -m unittest discover -s tests -p test_resource_limits.py -v

Stop a job with Ctrl+C to interrupt the child and keep an outcome receipt. A job killed by the memory limit can leave incomplete evidence; keep it.

The adaptive replay study trained 40 models in 419.2 seconds at 630.4 MiB peak memory. The partition study took 595.9 seconds at 343 MiB. All software checks pass before any scoring.

How to engage

Read one report end to end, including the section on what verification does not test. Then copy a plan, pick unused seeds, fix a rule, and run it under the launcher.
