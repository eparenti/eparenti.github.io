For software engineers and product builders who build with AI coding agents

Follow a written method for building software with AI coding agents.

The Field Manual is a set of documents that explains how to build software with AI coding agents (assistants that write and change code for you). It lists the practices that work and the evidence for each one, puts them in order as steps, and gives you a contract to hand the agent and templates to fill in. There is nothing to install. You read it and copy what you need into your project.

The problem. Most advice on building with AI agents is opinion. It rarely says what to do first, what to do next, or what to hand the agent, so good results are hard to repeat.

It is plain Markdown (text files with simple formatting) in one repository: the manual, the method, a contract for the agent, a guide for shaping a product idea, a starter project guide, ten checklists, twelve templates, and two worked examples.

Each practice comes with its evidence

A practice is in the manual only if several practitioners found it on their own, a study with data backs it, it shows up across many projects, or a dated failure on a real project produced it. Opinions are labeled as opinions.

The steps come in order

The method has 21 steps, from setting the goal through planning, building, review, release, and the definition of done. Checklists cover the main checkpoints.

The agent gets a short contract of its own

One self-contained file, short enough to load at the start of a session, tells the agent its role, how to build and review, and when to stop and ask the human.

Who reads which document

The two rules the rest supports. Use AI to do more work, and keep product judgment, authority, and release decisions with the human. Missing evidence must never be reported as success.

Your first hour with the method

The README gives a first hour you can follow on a real project: copy the starter guide, write a one-page brief, write one work packet, run the build loop, and read the quality section before you call anything done.

Example: the first hour

From the README
1. Copy STARTER-CLAUDE-MD.md into your project and fill in the
   environment, conventions, and security sections.
2. Write a one-page product brief (templates/product-brief.md).
3. Write one work packet for the first complete slice
   (templates/work-packet.md).
4. Run the build loop in METHOD.md section 11: failing test,
   implement, gates, diff, commit, stop for review.
5. Read FIELD-MANUAL.md section 7 before you call anything done.

A slice is one small piece of the product that works from end to end. Gates are the automated checks a change must pass. Section 7 of the manual covers quality and verification.

A practice belongs in the manual

It meets at least one evidence bar, and the manual cites its source. Personal preferences are left out.

A claim goes beyond its proof

The claims proof matrix and the definition of done show the gap. Nothing is called done because no test failed.

Who it is for. A software engineer or product builder, at any level, who uses AI coding agents to build software other people will use. It does not teach a specific tool, and it is not written for teams that build AI agents themselves.

Use it on a project today

Everything is Markdown. Copy what you need into your project, and keep the manual as the reference.

  1. If you own the project.

    Read FIELD-MANUAL.md for the practices, then METHOD.md for the steps. Copy STARTER-CLAUDE-MD.md into your project as its guide. Use the templates and CHECKLISTS.md at each checkpoint.

  2. For the coding agent.

    Hand it AGENT-CONTRACT.md with your project guide and the current plan.

  3. While the product is still an idea.

    Hand PRODUCT-DIRECTOR-MODE.md to any assistant. It proposes business rules, presents real options, and asks you only for the decisions that change the product.

Get it

git clone https://github.com/ostinato-forge/field-manual.git
cp field-manual/STARTER-CLAUDE-MD.md your-project/CLAUDE.md
cp field-manual/templates/product-brief.md your-project/docs/

Hand to the agent

# at the start of a session, with your project guide and current plan
field-manual/AGENT-CONTRACT.md

The starter guide can also be saved as AGENTS.md, the file name that several coding agents read. AGENTS.md in this repository holds the rules for editing the manual itself.
