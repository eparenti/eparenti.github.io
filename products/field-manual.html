For a software engineer or product builder working with coding agents

The practices, the method, the contract, the templates.

The Solo Builder's Field Manual is practical engineering with AI coding agents, grounded in evidence. The practices and why they work, the method that orders them, the operating contract you hand an agent, and the templates you fill in.

Three entry points: the human owner, the AI assistant, and product shaping. Written from building the repositories on this site.

Evidence-based practices

Every practice meets at least one bar: independently converged by multiple practitioners, empirically researched with data, repeatedly observed across real projects, or recorded as a dated incident with the rule it produced. Opinions are labeled.

A method in order

Goal, roles, rules, how much process, orient, decide, critique, contract, architecture, plan, build, review, red-team, prove, simplify, UX, release, improve, cost, failure modes, definition of done.

A contract for the agent

A self-contained operating contract sized to load at session start, plus a starter project guide and a product-director mode for when the product is still an idea.

Where each document is used

The two rules everything else serves. Use AI to increase capacity, and keep product judgment, authority, and release accountability with the human. Absence of evidence must never render as success.

From the first hour to a definition of done

The first hour is concrete: copy the starter guide, write a one-page brief, write one work packet, run the build loop, and read section 7 before calling anything done.

Example: the first hour

From the README
1. Copy STARTER-CLAUDE-MD.md into your project; fill in environment, conventions, security.
2. Write a one-page product brief (templates/product-brief.md).
3. Write one work packet for the first complete slice (templates/work-packet.md).
4. Run the build loop in METHOD.md section 11: failing test, implement, gates, diff, commit, stop for review.
5. Read FIELD-MANUAL.md section 7 before you call anything done.

CHECKLISTS.md has a checkpoint checklist for each step of the method.

A practice is in

It met at least one evidence bar and is cited. Preferences are left out.

A claim outruns its proof

The claims proof matrix and the definition of done catch it. Nothing is called done on the absence of evidence.

Who it is for. A software engineer or product builder, at any level, working with AI coding agents to build software other people will use. It is a manual. There is nothing to install.

Use it in a project today

Everything is Markdown. Copy what you need into the project; keep the manual as the reference.

  1. Human owner.

    Read FIELD-MANUAL.md for the practices, then METHOD.md for the steps. Copy STARTER-CLAUDE-MD.md as the project's operating guide. Use the templates and CHECKLISTS.md at each checkpoint.

  2. AI assistant.

    Hand it AGENT-CONTRACT.md with the project's own guide and current plan.

  3. Product shaping.

    Hand PRODUCT-DIRECTOR-MODE.md to any assistant while the product is still an idea. It proposes business rules, presents real options, and asks only for the decisions that change the product.
